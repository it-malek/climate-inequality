## 3. Duplicated logic

- **`app/data/*_summary.json` vs `data/processed/*_summary.json`** were
  byte-duplicated by a manual copy. This was the symptom of finding #1, not true
  logic duplication. Now both are emitted by `src.app_assets`
  (`build_decomposition_summaries`); `data/processed/` is the gitignored working
  copy, `app/data/` the committed deploy bundle. **Resolved.**
- **Path constants intentionally re-declared** in `app/loaders.py` and
  `src/app_assets.py` (`APP_DATA_DIR`) and in `app_assets.py` vs
  `validation.py`/`explain.py` (summary paths). This is deliberate — the
  deployed app cannot import the heavy pipeline modules — and is guarded by
  tests asserting the constants agree (`tests/test_app_assets.py`). **Keep.**
- **`summary_payload` appears in both `inequality.py` and `decomposition.py`.**
  Different dataclasses, same one-line shape (attach `INTERPRETATION_NOTE`, round
  floats). The shared piece (`round_floats`) was extracted to `src/data_io.py`
  this pass; the two thin wrappers are not worth merging. **Keep.**

## 6. Reproducibility & technical debt

### 6.1 Headline summaries were orphaned from the build (fixed — finding #1)

`src.app_assets.build_app_assets()` built the trends/anomalies/surface/inequality
assets and merged the Phase-6/7 findings, but **never produced
`inequality_summary.json` or `decomposition_summary.json`** — the two files that
drive the app's *default* (headline) page. They were copied into `app/data/` by
hand from `data/processed/`. A clean `python -m src.app_assets` therefore could
not regenerate the headline; the `decomposition.py` view's "not built yet"
message even instructed a manual copy.

**Fix:** added `src.app_assets.build_decomposition_summaries(...)`, mirroring the
existing `_merge_optional_findings` discipline (lazy imports; graceful skip with
a warning when the Phase-7 `city_features` / income inputs are absent — the page
then renders its pending state). `app_assets.main()` now calls it, so one
`python -m src.app_assets` regenerates the **entire** committed bundle. Covered
by `tests/test_app_assets.py::TestDecompositionSummaries`.

### 6.2 Non-deterministic decomposition JSON (fixed — finding #2)

Re-running `src.decomposition` reproduced the committed shares only to ~15
significant figures: e.g. `emissions = 0.08409736784540636` vs committed
`...633`. The drift is last-bit `numpy.linalg.lstsq`/BLAS noise that differs
across platforms and library versions, so the committed JSON was
environment-dependent and would show meaningless diffs on every rebuild.
(`inequality_summary.json`, simpler arithmetic, reproduced exactly.)

**Fix:** `src.data_io.round_floats(obj, ndigits=12)` rounds every float in the
serialized payload at the `summary_payload` chokepoint in both `inequality.py`
and `decomposition.py`. Twelve digits is far finer than the ~3 significant
figures the shares carry and invisible to the dashboard's `.0%`/`.3f`
formatting, but coarse enough to absorb the ~1e-16 noise. The committed
`app/data/*_summary.json` were regenerated through the new path and verified to
reproduce **byte-for-byte** into a separate directory. Covered by
`tests/test_data_io.py::TestRoundFloats` and a byte-stability test in
`TestDecompositionSummaries`.

### 6.3 Plotly `country names` deprecation (deferred — finding #8)

`app/charts.py:117` builds the country choropleth with
`locationmode="country names"`, which Plotly warns is changing. The robust fix
is to carry an ISO-3 code per country and switch to `locationmode="ISO-3"`.
Deferred because it needs a vetted country-name→ISO-3 mapping (a small data
addition with its own correctness surface — e.g. the Réunion/Puerto Rico edge
cases already noted in the README). Low user impact today; tracked in
`docs/release_checklist.md`.

### 6.4 Other debt observed, intentionally left as-is

- **Measurement uncertainty not propagated** into the trend fits
  (`AverageTemperatureUncertainty` unused) — a documented limitation and a
  `docs/future_work.md` item, not debt to fix here.
- **Spatial autocorrelation in country residuals** makes HC1 SEs optimistic.
  This is exactly what the shipped stability layer
  (`docs/stability_roadmap.md`) addresses — residual Moran's I ≈ 0.33 (p = 0.005),
  rendered on the sensitivity dashboard page; Conley HAC SEs remain roadmapped.

## 7. Notebooks (deferred — finding #9)

They carry embedded outputs (hence the large line counts) and are **exploratory

from `src/` modules with tests. They are harmless but undocumented. Recommended
(release-checklist item, not done here to avoid scope creep): add a one-line
`notebooks/README.md` stating they are exploratory/archival and that `src/` is
the source of truth, or strip outputs with `nbstripout`. No code depends on them.

## 8. Simplification opportunities

The codebase is already lean and consistent (centralized `app/theme.py` visual
language, a shared typed-parquet writer, dataclass results with invariant checks
like `check_sums_to_one`). The only simplifications taken were the consistency
fixes in §1 (#4–#6). No larger refactor is warranted; nothing was over-abstracted
or copy-pasted at a scale that justified restructuring.

## 9. CI / deployment

- **No CI workflow exists** (`.github/` is absent). Tests and ruff are run
  manually. For a v1.0 release this is the main infrastructure gap — a minimal
  GitHub Actions workflow (`uv sync --extra dev`, `ruff check`, `pytest`) would
  protect the green baseline and the reproducibility guarantees added this pass.
  Tracked in `docs/release_checklist.md`.
- **Deployment config is correct:** the app reads only the committed `app/data/`
  bundle; `app/requirements.txt` pins the minimal cloud stack and is picked over
  `uv.lock` by Streamlit Cloud (documented in the file and README); redeploys on
  push to `main`. No action.
